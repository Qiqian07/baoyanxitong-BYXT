## 管理员怎么建组织

不用再改代码或手工写数据库，按依赖顺序点几下就行：

1. **专业字典** → 新建专业（班级必须挂在专业下）
2. **班级管理** → 新建班级，选专业、填年级、指定辅导员
3. **学生名单** → 批量导入，或逐个「调整」把学生转进班级

**批量导入 CSV 格式**（首行表头可有可无，UTF-8 或 GBK 都认）：

```csv
学号,姓名,专业,班级,年级
2023099001,张三,工商管理,工商管理2301,2023
```

规则：

- 已存在的学号**跳过**，不覆盖——覆盖会把学生已录的绩点冲掉
- 专业名、班级名必须已存在，且班级必须属于该专业，否则该行报错跳过
- 新账号初始密码 `wt2026`，首次登录强制改密
- 导入完成后会提示「新增几名、跳过几名、哪几行有问题」

**辅导员为什么只看得到自己的班**：班级上分配了辅导员，辅导员登录后名单自动按班级过滤。名次仍是学院内口径，这样多个班之间能横向比较谁够得上保研线。

## 两个口径参数

`sys_config` 表里有两个值决定页面行为，改完刷新即生效，不用改代码：

| 键 | 默认值 | 作用 |
|---|---|---|
| `student_ranking_scope` | `strict` | `strict`＝学生端只看到本人名次与总人数（PRD 8.1 口径）；`full`＝展示完整脱敏榜单（公示场景） |
| `quota_current` | `12` | 本届保研名额，决定保研线与「名额内/外」判定 |

改法：`UPDATE sys_config SET value='full' WHERE key='student_ranking_scope';`

> 默认给 `strict` 是因为 PRD 8.1 和验收标准②要求「接口不返回任何其他学生姓名、学号或分数」。界面设计稿做的是完整榜单，两者冲突，这里按 PRD 走；确需公示时由学院改参数，不用改代码。

## 核心：评分引擎

`scoring.py` 是整个系统的心脏，公式写在 PRD 8.1：

```
综合成绩 = 绩点折算 × 绩点权重 + 竞赛折算 × 竞赛权重 + 论文折算 × 论文权重
         = (绩点 ÷ 5.0 × 100) × 85%
         + Σ(级别系数 × 团队排名系数) × 8%
         + Σ(分区基准分 × 作者系数) × 7%
```

三条设计原则，改代码前务必先读：

1. **权重和系数全部来自数据库**（`score_rule` 表），代码里没有任何魔法数字。管理员改规则，排名立刻变，不用改代码、不用重启。
2. **四舍五入用 Decimal 的 ROUND_HALF_UP**，不用 Python 内置 `round()`。内置是银行家舍入（2.5 → 2），学生拿计算器一按发现对不上，会认定系统算错了。
3. **同分并列同名次**，后续名次顺延（1、1、3），展示顺序用单项折算分做 tie-break，但不影响并列名次。
4. **单项排名零分不参与**。绩点 / 竞赛 / 论文三项各有一套学院内排名（PRD 8.1 要求）。该项得分为 0 的学生不进入该单项排名，页面显示「—」。否则 86 个无论文的学生会全部并列成「第 40 名」，看着像系统坏了。

演示账号「黄俊键」的数据是精心设计的：绩点 4.62 → 92.40，竞赛国家级一等 + 省级一等 → 88.00，论文 B 类独作 → 86.00，加权得 91.60，与界面设计稿完全一致。这不是写死的数字，是真跑了一遍引擎算出来的——如果哪天引擎算错，这个页面对不上，一眼就能发现。

## 和界面设计稿的差异

1. **不依赖 CDN**：Tailwind 换成本地文件，演示现场断网也不会白屏。
2. **榜单展示范围**：设计稿展示带脱敏姓名的完整榜单，PRD 8.1 要求「学生仅见本人名次与总人数」。**现在默认按 PRD 执行**（`student_ranking_scope=strict`）：学生端 `/student/ranking` 改为「我的位次」页，只下发本人一行数据。完整榜单的模板代码保留在 `ranking.html` 的 `full` 分支里，改参数即可启用，不需要改代码。辅导员与管理员端的完整名单不受影响。
3. **导航文案**：「材料填报」在原稿里是禁用态，本版已开放（V1.0 核心功能）。

## 安全说明

- 密码用 PBKDF2 哈希存储，数据库里看不到明文。
- 学生只能改自己的数据：所有增删改都会校验 `student_id` 归属，越权直接 404。
- **锁定后不可删改**：确认参与后，删除接口也会拒绝，不只是隐藏按钮（PRD 8.2）。
- **会话与登录**：所有 POST 校验 CSRF 令牌；连续 5 次密码错误锁定 30 分钟；30 分钟无操作会话失效；登录跳转只接受站内路径，挡住开放重定向。
- **口令规则**：≥8 位且须同时含字母与数字；首次登录强制改密。
- **CSV 导出**：对以 `= + - @` 开头的单元格做转义，挡公式注入。
- 权限按角色拦截，学生访问管理页返回 403；所有敏感操作写 `audit_log`。
- 生产部署前必须：设 `SECRET_KEY` 环境变量、不要开 `FLASK_DEBUG`、换成 MySQL 或 PostgreSQL、加 HTTPS。

## 常见问题

**页面样式乱了？** 确认 `static/js/tailwind.js` 存在。这个文件是本地 Tailwind，缺了会只剩基础样式。

**登录提示账号密码不正确？** 先确认跑过 `python seed.py`，数据库在 `instance/baoyan.db`。

**改了代码没生效？** 默认不自动重载（`debug` 已关闭）。用 `run.bat` 启动的按 Ctrl+C 再重开；要热重载就设环境变量 `FLASK_DEBUG=1`。

**写测试脚本直接 POST 全部返回 400？** V1.0.1 起所有 POST 都要带 CSRF 令牌：先 `GET /login`，从 HTML 里取出 `name="csrf_token"` 的值，再随表单一起提交。
